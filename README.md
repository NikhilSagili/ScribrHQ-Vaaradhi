# Vaaradhi Farms: subscription app demo

A clickable pitch demo for Vaaradhi Farms (Manikonda, Hyderabad). It has two connected apps, one for the customer and one for Vaaradhi. Customers can order for right now (same-day delivery), add to tomorrow's basket, or subscribe. Everything runs in the browser on sample data, with no backend.

- **Laptop or tablet** (900px wide or more): both phones side by side, connected live.
- **Phone:** one app at a time. Use the **Customer | Vaaradhi | How it works** switch at the top and the **Demo ▾** menu.
- **Install like an app:**
  - iPhone: open in Safari, tap Share, then **Add to Home Screen**.
  - Android: open in Chrome, tap the ⋮ menu, then **Install app** or **Add to Home screen**.

## Demo script (about 3 minutes)
1. **Home → tap ADD on a couple of items → View cart → Place order.** A new order pops up on Vaaradhi's Orders tab. Tap **Accept → Mark packed → Send out → Mark delivered** and watch the customer's tracker follow along.
2. **Plans tab → "Going out of town?" → 1 week.** Vaaradhi gets an alert, the prep sheet and revenue drop, and the wallet shows ₹0 for those days.
3. **Home → tap any product photo → Tomorrow → Add to tomorrow.** It appears on Vaaradhi's prep sheet for the morning.
4. **Home → Subscribe daily (under any product) → Start subscription.** It shows up in Vaaradhi's customers and tomorrow's list.
5. **Demo → Skip to 9:01 PM.** Customer edits lock, same-day ordering closes for the night, and Vaaradhi's list is ready to pack.
6. **Demo → Run morning deliveries,** or mark stops on the Run tab. The wallet is charged only for what was delivered, and Earnings shows collections settling to Vaaradhi's own payment account.

Use **Demo → Reset demo** before each pitch. State is saved in the browser and resets on its own each new day.

## Project layout
| Path | What it is |
|---|---|
| `index.html` | Page shell. Loads the files below. |
| `css/app.css` | All styles. |
| `js/app.js` | App logic and rendering (customer and merchant). |
| `data/catalogue.js` | **Product catalogue**: 50 curated Vaaradhi products with EkSecond displayed prices (verified 28 Oct 2026), categories, and **proposed** subscription eligibility per product. Generated by `tools/build_catalogue.py`; safe to hand-edit. |
| `data/plans.js` | **Breakfast plan concepts** (proposed, menu and pricing to be confirmed). |
| `data/config.js` | Asset mode: `placeholder` (public) or `brand` (local meeting copy only). |
| `data/catalogue-notes.md` | Sources, what is and isn't verified, unresolved variants and images, channel price differences. |
| `data/source/` | Raw captures: EkSecond (192 items) and the Shopify reference catalogue (78 products). |
| `tools/build_catalogue.py` | Rebuilds `data/catalogue.js` from the EkSecond capture. Edit the curated list and eligibility there. |
| `tools/make_meeting_copy.py` | Builds a **local-only** `meeting-copy/` with Vaaradhi's logo and product photos. Git-ignored; never publish it. |
| `tests/smoke.html` | Automated checks of catalogue, cart, checkout, subscriptions, lock and reload. |

## Editing
- **Products, prices, eligibility:** edit `CURATED`, `ELIGIBILITY` and `NOT_ELIGIBLE_ITEMS` in `tools/build_catalogue.py`, then run `python tools/build_catalogue.py`. Or edit `data/catalogue.js` directly.
- **Breakfast plans:** edit `data/plans.js` after the owner confirms menu, prices and capacity.
- **Brand assets:** the public demo uses neutral tiles. For the meeting, run `python tools/make_meeting_copy.py` and open `meeting-copy/index.html`.

## Tests
Serve the folder (`python -m http.server 8080`) and open http://localhost:8080/tests/smoke.html. All checks should show PASS.

## What is real and what is simulated
- **Verified:** product names and displayed prices from the EkSecond ordering page, captured 28 Oct 2026. Not synchronised.
- **Proposed:** subscription eligibility per product, breakfast plan concepts.
- **Simulated:** customers, orders, wallet balances and top-ups, payments, earnings, settlements, delivery times, notifications. No real money moves and no external service is connected.

## Running locally
```
python -m http.server 8080
```
Then open http://localhost:8080. To reach it from a phone on the same Wi-Fi, use your PC's IP address instead of localhost.

## Hosting (GitHub Pages)
1. Create an empty repo on GitHub, then add it as a remote and push: `git remote add origin <url>` and `git push -u origin main`.
2. In the repo, go to **Settings → Pages**, set the source to **Deploy from a branch**, and choose `main` / `/ (root)`.

The page has `noindex` set, so search engines won't list it.
